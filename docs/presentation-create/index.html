Presentation

Create

This group starts a new an empty PowerPoint presentation and holds it open in the workflow, so the instructions that follow can fill it. It is the usual way a workflow begins.

Prerequisite: none. This is an entry-point instruction: it does not need a document to exist beforehand — it makes one. To start from a file you already have, use the Opening group instead.

These concepts are explained here once.

  • File name and File path (the destination): where the document will be written when it is saved. The extension is added for you (.pptx).
  • Document: the Document key names the new document so later instructions can target it. If you leave it empty, the new document becomes the current document, which is what the instructions use when their own Document key is empty.
  • Nothing is written when this runs. The document is built in memory and reaches the disk when the workflow ends, or earlier if Save document runs. A workflow that fails writes nothing at all, so a half-made document is never left behind.
  • Dynamic values @name: every field in this group is a text field, so all of them accept a saved value: type @ followed by its name.
  • Create presentation

Create presentation

Creates an empty PowerPoint presentation (.pptx) and makes it the document the workflow works on.

When to use it: at the start of any workflow that produces a new file.

Parameter Meaning Default Required
File name Name of the file, without extension (accepts @name) (empty) To save
File path Folder the file will be saved to (accepts @name) (empty) To save
Document key Names the new document so later instructions can target it. Empty = current document (accepts @name) (empty) No

Important behavior: the document starts with one blank slide already in it, so Add slide adds the second one. If you add one slide per item, the first slide stays blank unless you write on it or delete it. File name and File path are only needed to save: without them the document is still created and can be worked on, but saving it fails and the workflow says so, naming the document by its key — give both unless the document is going to be thrown away with Close document. If the name in Document key is already in use by another open document, the workflow stops rather than discarding that document.
