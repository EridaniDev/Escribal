Text Doc

Character formatting

This group of instructions changes how the text itself looks: bold, italic, underline, strikethrough, small caps, font and size, text color, highlight, subscript/superscript, character spacing, and horizontal stretch. Each instruction finds the paragraphs whose text you want to affect and applies the formatting to their text.

Prerequisite: before using any of these instructions, the workflow must already have a DOCX document created or opened (with Create text doc), which these instructions will act upon.

These concepts recur across every instruction in this group; they are explained here once.

  • Document: indicates which document in the workflow the instruction applies to. If left empty, the current document is used.

  • Dynamic values (@name): in any text field you can type @ followed by the name of a value saved earlier in the workflow, and it will be replaced by that value. For example, if you saved a color in brandColor, you can type @brandColor in the Color field.

  • Search text — which text is affected: every instruction has a Search text field that decides which text it changes. The formatting is applied to the text of every paragraph whose text contains the search text. If Search text is left empty, the instruction applies to all paragraphs in the document.

  • Enable — turning formatting on or off: several instructions (bold, italic, small caps, strikethrough, underline, vertical alignment) have an Enable switch. Set it to Yes to apply the formatting, or No to remove it from the matching text.

  • Case sensitive: decides whether the Search text match distinguishes between upper- and lower-case. It is off by default (so Title also matches title).

  • Measurement units and colors: font size and character spacing are given in points (pt); horizontal scale is a percentage; colors are given as hex codes (for example FF0000 for red), with or without a leading #.

  • Save a result (Save count in): every instruction in this group can store how many paragraphs it affected under a name you choose, so a later instruction can reuse it. Leaving the field empty saves nothing. The number counts matched paragraphs, not occurrences of the search text: a paragraph that contains the search text three times counts once, and with Search text empty the number is simply how many paragraphs the document has. It is useful to check whether a search matched anything at all — pair it with a Condition to skip later steps when the count is 0. The paragraph-formatting group offers the same field.

  • “From variable” fields: the @name trick only works in text fields. So that a numeric field (like Size or Spacing) or a yes/no field (like Enable) can also take its value from a saved value, each one has a companion “from variable” field:

    • If you leave it empty, the value typed in the normal field is used.
    • If you fill it in with the name of a saved value, the engine ignores the normal field and uses that variable’s value.

    This is mainly for chaining instructions (one instruction saves a value, the next one reads it). If you only work with fixed values, you can ignore these fields.

Apply Bold .docx

Makes the matching text bold, or removes bold from it.

When to use it: to emphasize words or headings in bold.

Parameter Meaning Default Required
Document Document the instruction applies to (current document) No
Search text The text of paragraphs containing this text is affected; empty = all. Supports @name (empty) No
Enable Yes applies bold, No removes it Yes (apply) No
Case sensitive Whether the search-text match is case-sensitive No No
Enable (from variable) Reads the yes/no value from a saved value (empty) No
Case sensitive (from variable) Reads the yes/no value from a saved value (empty) No
Save count in Name under which to save how many paragraphs were modified (empty) No
